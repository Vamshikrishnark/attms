ATTMS · free Community edition · Windows

One test bench for the whole vehicle-to-portal chain

Most testing tools are excellent at one layer: the web UI, the test plan, or the CAN bus. ATTMS tests across all of them in one case, and runs offline on a lab PC.

Where ATTMS fits

One offline, all-in-one workbench for testers: web, desktop, SAP, APIs, data pipelines and vehicle diagnostics in the same test case, with the evidence kept. It works alongside the tools your team already uses.

A typical end-to-end check

Today this needs four tools glued together

Send CAN signal→ Check Kafka / database→ Check the web portal→ Read ECU fault codes (UDS)→ Link result to the story

In ATTMS it is one case, one run and one report.

Why testers use it

Strengths

  • One case across every layer: UI, APIs, data pipelines and vehicle diagnostics.
  • Built for plants and labs: self-hosted, offline-capable, runs on standard PCs.
  • Traceability included: stories, reviews, releases and defects, ready for ASPICE audits.
  • No big-bang migration: existing Cucumber, Robot and Playwright suites keep running, then convert step by step.
  • Testers, not only developers: recording, plain-English steps and a German interface.
Made for

Who it is for

  • Manual testers moving to automation - record or write steps in plain English, no code.
  • System and integration test teams covering ECU, backend and portal together.
  • Teams on isolated networks where cloud tools are not allowed.
  • Automation engineers who want their existing Playwright, Robot or Cucumber suites in one place.
