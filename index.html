Why ATTMS

One end-to-end test usually means one tool for the web, another for the API, a script for the database and a spreadsheet for results.

ATTMS puts it all in one test case, one run and one report. Testers write and run it, without waiting for a developer.

What you can test

Almost anything your team ships

Use one kind of step or mix them in the same case. It works for banking, insurance, retail, SAP projects, in-house apps and connected vehicles.

Websites and web apps

Click, type, check text and take screenshots in Chrome, Edge or Firefox. Record your clicks to build steps.

Windows desktop apps

Test thick-client and back-office applications with the desktop recorder.

SAP GUI

Transactions, fields, tables and grids, recorded and replayed.

APIs

REST calls with checks on status, body and fields, chained with your UI steps.

Databases and data pipelines

SQL, MongoDB, Kafka and S3. Check that the data matches what the screen shows.

Mobile apps

Android apps on a phone or emulator (via Maestro), in the same case as your web steps.

Vehicles and ECUs

CAN signals and UDS/DoIP diagnostics for automotive teams, as one more kind of step.

Your existing tests

Run Playwright, Cucumber, Robot and JUnit suites from ATTMS, then convert them step by step.

How it works

From idea to report in three steps

Write or record the test

Type steps in plain English, record clicks in the browser, desktop or SAP, or let the local AI draft cases from a user story for you to review.

Run it, on one PC or many

Run a single case or a whole suite now or on a schedule. Agents on other PCs or lab machines can run them in parallel.

See what happened

Each run keeps screenshots, logs and timing. A failure comes with a plain-language explanation, and results link back to your stories and releases.
